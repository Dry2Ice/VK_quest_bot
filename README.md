# VK QR-квест бот (Pro Hard & Soft)

Бот на `vkbottle`, реализующий сценарий из ТЗ: регистрация → проверка подписки →
поиск QR2 → капча с подсказкой про кассира → поиск QR3 → ребус → ответ → билет на
Колесо Фортуны. Прогресс каждого пользователя — жёсткая машина состояний, шаги
нельзя пропустить (проверено smoke-тестом, см. ниже).

## Актуальный сценарий квеста

После QR2 бот присылает первую картинку — капчу. Участник должен отправить слова
«магазин» и «кассир» в любом порядке; подсказка говорит взять ответ у кассира.
После верной капчи бот не показывает адрес QR3, а просит найти третий QR. QR3
возвращает участника в бот и присылает вторую картинку — ребус. Видео пока не
используется.

## Структура проекта

```
config.py      — все настройки (токены, тексты локаций, коды чекпоинтов)
texts.py       — все сообщения бота (правьте смело, логику не трогает)
keyboards.py   — инлайн-кнопки
utils.py       — валидация имени/телефона, проверка ответа, генерация ID билета
db.py          — локальная SQLite: источник истины для состояния диалога
sheets.py      — синхронизация состояния в Google-таблицу
handlers.py    — вся логика/машина состояний квеста
main.py        — точка входа
requirements.txt
.env.example   — шаблон конфига
```

## Почему БД — SQLite, а не сразу Google Sheets

Вы просили "базу данных в гугл-таблице" — она будет, и в реальном времени.
Но использовать саму таблицу как хранилище состояния диалога рискованно:
у Sheets API заметная задержка и лимиты на число запросов в минуту, а на
каждый шаг диалога (их 7–8 на человека) нужно читать/писать данные. При
нескольких участниках одновременно бот будет тормозить или упрётся в лимит,
а любая сетевая заминка может сломать логику "нельзя пропустить этап".

Поэтому сделано так: **источник истины — локальная SQLite** (`quest.db`,
создаётся автоматически рядом с ботом) — быстро, атомарно, работает даже
если Google на секунду недоступен. А **Google-таблица — зеркало-витрина**:
после каждого шага бот дозаписывает/обновляет строку пользователя в таблице.
Открыть таблицу по ссылке можно в любой момент — она отражает актуальное
состояние с задержкой в доли секунды.

Если трафик от квеста будет небольшим и вам принципиально важно, чтобы
именно таблица была единственным хранилищем — дайте знать, я пересоберу
`db.py` на прямую работу через `sheets.py` без SQLite, просто это менее
надёжно при живой нагрузке.

## Настройка

### 1. Токен и ID сообщества VK

1. В сообществе Pro Hard & Soft: **Управление → Работа с API → Ключи доступа**
   → создать ключ с правами **«Сообщения сообщества»**.
2. Там же посмотрите числовой **ID сообщества** (не screen_name, а число).
3. В **Управление → Настройки → Сообщения** включите приём сообщений и
   **Long Poll API** (Управление → Работа с API → Long Poll API → «Включено»,
   в типах событий должно быть отмечено «Новое входящее сообщение»).
4. Заполните `VK_TOKEN`, `VK_GROUP_ID`, `COMMUNITY_SCREEN_NAME` в `.env`.

### 2. QR-коды

Все три QR-кода ведут на диплинки вида «написать сообщение сообществу» —
квест стартует **только** от правильного кода QR1, а не от любого случайного
сообщения в диалоге (в том числе от стандартной кнопки «Начать диалог» — она
квест не запускает):

```
https://vk.ru/write-<VK_GROUP_ID>?ref=<REF_CHECKPOINT_1>   — уличный QR, старт квеста
https://vk.ru/write-<VK_GROUP_ID>?ref=<REF_CHECKPOINT_2>   — локация 1
https://vk.ru/write-<VK_GROUP_ID>?ref=<REF_CHECKPOINT_3>   — локация 2
```

**Важно про домен:** с июля 2026 VK полностью переехал на домен `vk.ru`,
`vk.com` постепенно отключается и вести себя предсказуемо на нём больше не
гарантировано — используйте только `vk.ru`. Сама библиотека `vkbottle`
(начиная с версии, которая встанет по `requirements.txt`) уже сама ходит в
API через `api.vk.ru`, отдельно ничего настраивать не нужно.

где `REF_CHECKPOINT_1/2/3` — секретные строки из `.env` (замените дефолтные
на свои случайные, не совпадающие с обычными словами, чтобы их нельзя было
угадать/напечатать случайно). Параметр `ref` — официально задокументированный
у VK механизм: он попадает в объект сообщения (поля `ref`/`ref_source`), если
человек после перехода по ссылке отправит **любое** сообщение — контент
сообщения неважен, важен только сам факт перехода по ссылке с этим `ref`.

Так как автоматической отправки сообщения по такой ссылке нет (в отличие,
например, от Telegram, у VK нет официально задокументированного `?text=` для
предзаполнения поля ввода), после перехода по ссылке человек попадёт в
**пустой диалог**, и нужно, чтобы он сам отправил хоть что-то. Чтобы это было
одним тапом, а не набором текста вручную:

- Включите в сообществе кнопку **«Начать диалог»**: Управление → Настройки
  → Сообщения → «Показывать кнопку начала диалога». Тогда вместо пустого поля
  ввода человек увидит кнопку «Начать» — один тап по ней уже считается первым
  сообщением, и `ref` к нему приклеится.
- Либо просто напишите на самой QR-табличке что-то вроде «Отсканируй и
  напиши любое сообщение, чтобы начать квест!».

Бот дополнительно (на всякий случай) проверяет и параметр `?text=` — если
он всё-таки где-то предзаполнится (в некоторых клиентах VK такое бывает),
чекпоинт тоже засчитается. Но полагаться на это как на единственный
механизм не стоит — основной сценарий именно `ref` + один тап на кнопку
«Начать» или короткое сообщение.

**При тестировании ссылок:** они открываются корректно только если
браузер/приложение авторизовано в VK. Открытая в неавторизованном браузере
или приватной вкладке ссылка покажет общую страницу
«vk.me/vk.ru — быстрый доступ к обмену сообщениями» вместо перехода в
диалог — это не баг бота, а поведение самого VK. Тестируйте либо с телефона
через приложение VK (так это и будет работать на реальном квесте), либо в
браузере, где вы залогинены на vk.ru.

### Кнопка «Я отсканировал QR»

Под сообщениями с локациями QR2 и QR3 есть кнопка «Я отсканировал QR» — это
не автоматическое подтверждение факта сканирования (технически VK не
позволяет ссылке молча слать сообщения за человека, это разобрано в чате
разработки бота), а честная ручная проверка текущего состояния:

- Если код чекпоинта (через `ref`/`text` по физической QR-ссылке) **ещё не
  дошёл** до бота — кнопка вежливо об этом скажет и предложит нажать снова
  после перехода по QR.
- Если код уже зафиксирован — подтвердит и покажет актуальное задание.

Состояние пользователя кнопка никогда не продвигает сама по себе — она
только читает то, что уже реально произошло.

Если человек просто откроет диалог с сообществом и напишет что-то своё (или
найдёт сообщество через поиск и нажмёт «Написать сообщение») — квест не
активируется, бот ответит нейтральной подсказкой «этот квест начинается со
сканирования QR-кода» и не создаст запись участника. Это можно поменять в
`texts.NOT_STARTED_HINT`.

Если у сообщества включена стандартная кнопка «Начать диалог» (Управление →
Настройки → Сообщения) — по ней тоже ничего не запустится, так что можно
смело оставить её включённой или выключить, на логику это не влияет.

Сгенерировать сами QR-картинки можно любым онлайн-генератором QR по этим
URL, либо через `pip install qrcode[pil]` и пару строк Python — если нужно,
могу сразу сделать генератор QR-кодов с блюром/оформлением под бренд.

### 3. Google Sheets

1. Google Cloud Console → создать проект → включить **Google Sheets API**
   и **Google Drive API**.
2. **IAM & Admin → Service Accounts** → создать сервисный аккаунт → создать
   для него JSON-ключ → сохранить как `credentials.json` рядом с ботом
   (файл секретный, не публикуйте).
3. Создать саму Google-таблицу, открыть **Настройки доступа** и:
   - расшарить на e-mail сервисного аккаунта (поле `client_email` в
     `credentials.json`) с правом **Редактор** — иначе бот не сможет писать;
   - отдельно настроить **«Доступ по ссылке»** для людей, которым вы сами
     хотите показывать таблицу.
4. ID таблицы — это часть ссылки между `/d/` и `/edit`:
   `https://docs.google.com/spreadsheets/d/ЭТОТ_КУСОК/edit`.
5. Впишите `GOOGLE_SHEET_ID` и путь к `credentials.json` в `.env`.

Обратите внимание — это **два разных доступа**, оба нужны:
- доступ **сервисного аккаунта** (по `client_email`) — чтобы бот мог
  писать в таблицу. Без этого шага бот получит ошибку прав при первой же
  попытке синхронизации;
- доступ **по ссылке для людей** — чтобы вы (и кто вам нужно) могли открыть
  и посмотреть таблицу в браузере. Это два независимых переключателя в
  окне «Настройки доступа» — сервисный аккаунт туда всё равно придётся
  добавить отдельной строкой, «доступ по ссылке» на него не распространяется.

Если `GOOGLE_SHEET_ID` не заполнен — бот просто работает без синхронизации
в таблицу (это удобно для первого локального теста без Google-доступа).

### 4. Тексты и медиа (свои картинки)

- Подсказка для QR2 — `QR2_LOCATION_TEXT` (по умолчанию координаты `55.741186, 37.502687`), адрес QR3 больше не используется, призовой адрес — `PRIZE_ADDRESS`.
- Все тексты сообщений — в `texts.py`, можно править без риска сломать логику.
- **Картинки бот берёт прямо из папки `media/` рядом с ботом** —
  никаких attachment-строк вручную получать не нужно. Положите файлы под
  именами по умолчанию (см. `media/README.md`):

  ```
  media/captcha.jpg  — капча после QR2
  media/rebus.jpg    — картинка с ребусом после QR3
  ```

  При первом старте бот сам загрузит эти файлы в VK через
  `photos.getMessagesUploadServer` и запомнит готовые attachment-строки в
  `media_cache.json` рядом с ботом — при следующих перезапусках повторно
  грузиться будет только файл, который вы заменили.

  Имена файлов можно поменять через `.env` (`CAPTCHA_PHOTO_FILE`,
  `REBUS_PHOTO_FILE`), а папку — через `MEDIA_DIR`. Если для картинки уже есть
  attachment-строка, впишите её в `CAPTCHA_PHOTO_ATTACHMENT` или
  `REBUS_PHOTO_ATTACHMENT`.

## Где хостить

Бот держит постоянное соединение с VK (Bots Long Poll API) — то есть ему
не нужен ни белый IP, ни входящий webhook, ни домен/SSL. Годится буквально
любая машина с постоянным аутбаунд-доступом в интернет и Python 3.11+,
которая не выключается:

- Любой недорогой VPS (Timeweb Cloud, Selectel, Beget Cloud, REG.RU,
  Yandex Cloud и т.п. — не принципиально, бот ничего специфичного от
  провайдера не требует).
- Домашний ПК/сервер, если он не выключается и не уходит в сон — тоже
  подойдёт, но для продакшн-квеста надёжнее отдельная машина.

Важно на любом хостинге:
- диск должен быть **постоянным** (persistent) — на нём живут `quest.db`
  (прогресс участников), `media_cache.json` (кэш загруженных картинок) и
  `credentials.json` (ключ Google) — при пересоздании контейнера/машины
  без сохранения диска прогресс участников потеряется;
- `.env` и `credentials.json` не должны попадать в публичный git-репозиторий.

Проще всего запускать как systemd-сервис, чтобы бот сам поднимался после
перезагрузки сервера и рестартовал при падении:

```ini
# /etc/systemd/system/vk-quest-bot.service
[Unit]
Description=VK Quest Bot
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/vk_quest_bot
ExecStart=/opt/vk_quest_bot/venv/bin/python main.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now vk-quest-bot
sudo journalctl -u vk-quest-bot -f   # логи
```

Если удобнее Docker — заведите обычный `Dockerfile` (`FROM python:3.12-slim`,
`COPY`, `pip install -r requirements.txt`, `CMD ["python", "main.py"]`) и
том (`volume`) на директорию с ботом, чтобы `quest.db`/`media_cache.json`
переживали пересоздание контейнера. Могу собрать `Dockerfile` и
`docker-compose.yml`, если решите, что так удобнее — скажите.

## Что хранится по каждому участнику (и в SQLite, и зеркалом в Sheets)

- VK ID, имя, телефон
- ID билета (после успешного завершения)
- время начала квеста, время подтверждения подписки, время сканирования
  QR2, время сканирования QR3, время завершения
- текущий этап
- список пройденных чекпоинтов
- **все** варианты ответа на ребус с таймстампами и пометкой верный/неверный
  (не только последний — так видно, кто и сколько раз пытался угадать)

## Как проверялась логика

В процессе разработки я прогонял полный сценарий прохождения квеста через
фиктивные сообщения (без реального VK и Google), включая намеренные попытки
нарушить порядок: досрочно прислать код QR2/QR3, повторно отсканировать один
и тот же QR, написать что-то до регистрации и т.д. — во всех случаях состояние
пользователя не откатывается и не перепрыгивает вперёд, бот просто напоминает
текущее задание. Тестовый скрипт не включён в поставку (не нужен в проде),
но при желании я могу прислать его отдельно или превратить в постоянный
`tests/` в проекте.

## Проверка подписки — насколько это надёжно

Бот вызывает `groups.isMember(group_id=VK_GROUP_ID, user_id=...)` —
именно на `VK_GROUP_ID` из `.env`, то есть проверяется подписка ровно на
то сообщество, чей токен использует бот. При вызове с одним `user_id`
(не списком) этот метод официально возвращает просто `true`/`false`,
без дополнительных полей — в коде это значение используется напрямую, без
самодеятельных допущений. Токена сообщества достаточно, отдельные
разрешения на это не нужны.

Единственный нюанс, который стоит держать в голове: если по каким-то
причинам сообщество закрытое/приватное — сама механика вступления другая
(заявки на вступление), и `isMember` в этом случае корректно покажет
`false` до одобрения заявки. Для обычного открытого паблика (какой,
судя по всему, у Pro Hard & Soft) всё работает "из коробки" — проверено
разбором сигнатуры метода в `vkbottle_types`, а не по памяти.

## Известные ограничения / что стоит обсудить

- Капча после QR2 принимает слова из `CAPTCHA_WORDS` в любом порядке: «магазин кассир»
  или «кассир магазин».
- Список принятых ответов на ребус (`ACCEPTED_ANSWERS` в `config.py`) сейчас
  — `{"зарядку", "зарядка"}`, сравнение регистронезависимое. Добавить ещё
  варианты — одна строка.
- Валидация имени/телефона намеренно мягкая (чтобы не отсеивать реальных
  людей за нестандартный ввод) — если нужна более строгая проверка телефона
  под конкретный формат, скажите.
- Видео-инструкция и итоговое фото Бипа — просто attachment-строки, дизайн/
  контент этих медиа не создавался (в задаче не было исходников).
